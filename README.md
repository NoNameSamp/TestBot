# Vika Birthday Bot

Telegram-бот с большой кнопкой «Поздравить Вику с Днём Рождения» и автопостом
поздравлений от Gemini каждые 3 часа.

## Что делает бот

- При `/start` показывает reply-клавиатуру с одной большой кнопкой.
- При нажатии на кнопку генерирует новое поздравление через Gemini и присылает его в чат.
- Раз в 3 часа (настраивается) сам генерирует и присылает поздравление в указанный чат — без нажатий.

## 1. Подготовка

### 1.1. Токен бота
Если хотите **заменить существующего бота новым функционалом** — не создавайте нового,
а используйте токен уже существующего бота (см. раздел «Замена старого бота» ниже).

Если нужен новый бот — напишите [@BotFather](https://t.me/BotFather) → `/newbot`.

### 1.2. Ключ Gemini
Получите бесплатный API-ключ на https://aistudio.google.com/apikey

### 1.3. ID чата
Добавьте бота в группу, затем узнайте ID чата любым способом:
- добавьте в группу [@getidsbot](https://t.me/getidsbot) — он покажет ID (у групп он отрицательный, например `-1001234567890`);
- либо перешлите любое сообщение из группы боту [@userinfobot](https://t.me/userinfobot).

## 3. Деплой на Render.com (бесплатно, через Web Service + UptimeRobot)

Бот работает через long polling, но у него есть встроенный лёгкий HTTP-сервер
(`bot.py`, эндпоинт `/`), который отвечает `200 OK`. Это нужно для двух вещей:
1. Render Free Web Service требует, чтобы сервис слушал порт — иначе деплой считается неудачным.
2. UptimeRobot будет пинговать этот адрес каждые 5 минут, чтобы сервис не засыпал
   (Render Free усыпляет Web Service после 15 минут без HTTP-запросов).

### 3.1. Деплой на Render

Через Blueprint (проще всего — в репозитории уже есть `render.yaml` с `plan: free`):
1. https://dashboard.render.com → **New** → **Blueprint**.
2. Подключите GitHub-репозиторий `vika-birthday-bot`.
3. Render попросит ввести `BOT_TOKEN`, `GEMINI_API_KEY`, `CHAT_ID` — впишите значения.
4. **Apply**. Render соберёт и задеплоит сервис как **Web Service** на бесплатном плане.
5. После деплоя у сервиса появится публичный адрес вида
   `https://vika-birthday-bot-xxxx.onrender.com` — он понадобится для UptimeRobot.

Либо вручную:
1. **New** → **Web Service** → подключить репозиторий.
2. Runtime: Python 3. Instance Type: **Free**.
3. Build Command: `pip install -r requirements.txt`
4. Start Command: `python bot.py`
5. Environment → добавить `BOT_TOKEN`, `GEMINI_API_KEY`, `CHAT_ID` (и опционально остальные).
6. **Create Web Service**. Скопируйте выданный Render URL.

> Render сам передаёт порт через переменную `PORT` — бот уже читает её (`bot.py`), ничего
> дополнительно указывать не нужно.

### 3.2. Настройка UptimeRobot

1. Зарегистрируйтесь на https://uptimerobot.com (есть бесплатный план).
2. **+ Add New Monitor**.
3. Monitor Type: **HTTP(s)**.
4. Friendly Name: например `Vika Birthday Bot`.
5. URL: вставьте адрес сервиса Render, например
   `https://vika-birthday-bot-xxxx.onrender.com/`
6. Monitoring Interval: **5 minutes** (минимальный интервал на бесплатном плане UptimeRobot —
   этого достаточно, чтобы Render не успевал усыпить сервис за 15 минут простоя).
7. **Create Monitor**.

Готово — теперь UptimeRobot будет каждые 5 минут дергать бота, он не будет засыпать,
и внутренний таймер на 3 часа будет срабатывать стабильно.

> Небольшая оговорка: раз в некоторое время Render всё равно может перезапустить бесплатный
> инстанс (редеплой, технические работы и т.п.). При перезапуске таймер на автопоздравление
> начнёт отсчёт заново (`FIRST_RUN_DELAY` секунд после старта), так что интервалы между
> автопоздравлениями могут иногда немного «плавать». Для полной стабильности — платный
> Background Worker ($7/мес), но для чата на 14 человек описанного варианта с UptimeRobot
> вполне достаточно.

## 4. Замена старого бота новым функционалом

Если хотите, чтобы вместо старого бота в той же группе работал этот — есть два пути:

**А. Использовать токен старого бота (рекомендуется — не нужно ничего перевыпускать)**
1. Возьмите токен существующего бота (тот, кто его создавал, может получить его заново
   через `@BotFather` → `/mybots` → выбрать бота → `API Token`).
2. Впишите этот токен в переменную `BOT_TOKEN` нового сервиса на Render.
3. **Остановите/удалите старый сервис**, где сейчас запущен код этого бота (иначе Telegram
   будет ругаться конфликтом `getUpdates`, так как два процесса не могут одновременно
   поллить один и тот же токен). Проще всего — в старом хостинге (Render/VPS/etc.) остановить
   или удалить старый сервис/деплой.
4. Задеплойте новый код (см. раздел 3) с этим токеном — бот в чате останется тем же
   (то же имя, аватар, история), просто с новым поведением.

**Б. Завести нового бота**
1. Создайте нового бота через `@BotFather`, получите токен.
2. Добавьте нового бота в группу, дайте права отправки сообщений.
3. Удалите старого бота из группы (или просто остановите его сервис, если не хотите удалять из чата).
4. Задеплойте с новым токеном.

Вариант А проще для пользователей чата — они не заметят подмены, кроме нового поведения.

## 5. Локальный запуск (для проверки перед деплоем)

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env       # заполните реальными значениями
export $(grep -v '^#' .env | xargs)   # или используйте python-dotenv
python bot.py
```

## 6. Настройка через переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен от BotFather |
| `GEMINI_API_KEY` | да | — | ключ Gemini API |
| `CHAT_ID` | да | — | ID группы для автопоздравлений |
| `BIRTHDAY_NAME` | нет | Вику | имя именинницы (в винительном падеже, для текста) |
| `BUTTON_TEXT` | нет | 🎉 Поздравить Вику с Днём Рождения | текст на кнопке |
| `GEMINI_MODEL` | нет | gemini-2.5-flash | модель Gemini |
| `INTERVAL_SECONDS` | нет | 10800 (3 часа) | период автопоздравлений в секундах |
| `PORT` | нет (задаёт Render) | 10000 | порт для health-check сервера |
